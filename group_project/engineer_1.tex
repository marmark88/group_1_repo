\section{RNAsik: A Pipeline for complete and reproducible RNA-seq analysis that runs anywhere with speed and ease \cite{rnAsik2019}}

\paragraph{
    The RNAsik pipeline was successfully installed and executed by creating a dedicated Conda environment and installing the package from the available bioconda channel. Following installation, the pipeline was able to launch and display its usage and configuration options, confirming that the software itself was functional and correctly set up. However, full reproduction of the original test results described in the project documentation was not possible due to external data accessibility issues. Specifically, the pipeline relied on remote datasets hosted via HTTP/FTP links, which were either inaccessible (HTTP 403 Forbidden errors) or failed to resolve correctly when used within the execution workflow. Attempts to retrieve the required input data using the provided GitHub scripts were unsuccessful, preventing the pipeline from completing the intended test run. As a result, the exact computational workflow and expected outputs described in the documentation could not be replicated. This limitation appears to be unrelated to the core functionality of the RNAsik software itself and instead arises from external dependency and data-hosting availability issues. While the pipeline installation and command-line interface were verified as operational, a suitable substitute dataset was not identified within the scope of this work to enable full end-to-end replication. Therefore, the study can be considered partially reproducible in terms of software deployment, but not fully reproducible in terms of data results. Engineer: Mark Cubi
}

\section{SPEAQeasy: a scalable pipeline for expression analysis and quantification for R/bioconductor-powered RNA-seq analyses \cite{Eagles2021SPEAQeasy}}

\paragraph{
    The SPEAQeasy pipeline was successfully installed and executed within a Windows Subsystem for Linux (WSL2) environment using Docker and Nextflow. The workflow was able to initialize correctly, load the test dataset, and progress through multiple validation steps, including sample parsing, strand specification, and reference genome selection. However, full execution of the pipeline was not feasible on the available hardware due to system resource constraints. During runtime, the process failed at the genome assembly download and preparation stage, where the pipeline required approximately 4 GB of memory but only ~3.7 GB was available within the WSL2 environment. Despite attempts to adjust input parameters and execution profiles, the limitation persisted due to my local machine's total 8 GB RAM capacity and the additional overhead introduced by running a virtualized Linux environment alongside Docker containers. This indicates that while SPEAQeasy is functionally reproducible in terms of installation and configuration on the system, complete end-to-end execution of the full RNA-seq workflow is not feasible on my hardware. The results suggest that successful reproduction of the pipeline’s intended analysis requires a higher-memory computing environment, and that performance limitations rather than software incompatibility prevented full replication of the published workflow. Engineer: Mark Cubi

\section{Identification of hot spring Obelisk-like RNA replicons and expanded diversity of the Obelisk superfamily \cite{Urayama2026ObeliskRNA}}

\paragraph{
    The FLDS toolkit was intended to replicate the read-cleaning and terminal structure identification steps used in that study’s workflow, which is essential for reconstructing full-length circular RNA genomes from raw Illumina metatranscriptomic reads. The pipeline was successfully obtained and partially configured in a Windows Subsystem for Linux (WSL2) environment, and the sample list generation and script structure were correctly adapted to local FASTQ data paths. However, full implementation of the pipeline was not feasible due to major dependency and environment constraints. Several required tools (including Cutadapt, SortMeRNA, PRINSEQ++, and Bowtie2 index configurations) were either unavailable through Conda or required manual installation and version-specific compilation, and resolving these dependencies within WSL introduced persistent compatibility and pathing issues across the chained Perl scripts. Additionally, even if I fully installed this, the pipeline is computationally heavy. While the workflow could be structurally set up, it was not possible to execute the complete end-to-end FLDS processing and terminal mapping steps required to reconstruct viral circular RNA genomes as described in the original research. This indicates that faithful reproduction of the Obelisks discovery pipeline would likely require a pre-configured high-performance computing environment or containerized system matching the original authors’ setup, rather than a local WSL-based installation. Engineer: Mark Cubi

\section{Phage-assisted evolution of allosteric protein switches \cite{Southern2026}}

\paragraph{
The computational analysis pipeline for the study "Phage-assisted evolution of allosteric protein switches" was assessed for reproducibility within a Windows Subsystem for Linux (WSL2) environment using a laptop with 8 GB RAM. The study provided well-documented resources including a GitHub repository with R and Python analysis scripts, a conda environment.yml file, raw and processed sequencing data on Zenodo, flow cytometry data, and plasmid sequences on Addgene. However, several setup issues required resolution before any figures could be reproduced.
The conda environment was created using the provided environment.yml, but required three additional steps: adding the conda-forge and bioconda channels to resolve missing packages, and manually removing the python.app entry from the environment file, which is a macOS-only package incompatible with Linux. The flow cytometry analysis in various figures required a completely separate conda environment due to the cytoflow package being incompatible with the modern versions of numpy, matplotlib, and seaborn present in the main environment, an issue acknowledged in the notebook itself. Both environments were registered as separate Jupyter kernels to allow switching within the same notebook session. Additional packages scipy and biopython were also absent from the environment specification and required manual installation. A bug was identified in various figure notebooks where the variable "repository root" was not defined, despite being required for data path resolution. This was resolved by manually adding the path definition cell.
Data extraction required selective unzipping of specific experiment folders from the 16.9 GB Zenodo archive rather than full extraction due to disk space constraints. Large JSON alignment files (~70 MB) caused severe performance degradation when read across the WSL2/Windows filesystem boundary (/mnt/c/), requiring the working directory to be migrated to the native Linux filesystem to restore normal I/O performance.
Flow cytometry figures (Figure 2, 2G, and 4) were successfully reproduced end-to-end, with output plots qualitatively consistent with the published figures. Reproduction of the Illumina sequencing analysis notebooks was also achieved after loading their processed data. All figure notebooks were successfully executed with output plots qualitatively consistent with the published figures. I could not reproduce the raw data processing pipeline because of hardware limitations and the computational demands of reprocessing raw sequencing data on a consumer laptop. These results indicate that the study is largely reproducible on standard hardware. Engineer: Mark Cubi}
